# Benchmarks

## Directory-walk scanner, 1 M empty files (2026-10-12)

Machine: Windows 10 22H2, Lexar 512 GB NVMe (C:), release build.
Tree: 1,000 folders × 1,000 empty files under `%TEMP%` (generated by the ignored test
`cargo test -p diskdash-core --release --test scan -- --ignored bench --nocapture`).

| Mode | Threads | Time | Files/s |
|---|---|---|---|
| Hard-link detection on (one metadata open per file) | 4 | 20.8 s | ~48,000 |
| Hard-link detection off | 4 | 7.4 s | ~135,000 |

## Real drive: C: through the API (2026-10-12)

Release build, non-elevated, hard-link detection on (system volume default), 4 SSD threads.

| Metric | Value | Spec target |

Cross-check: `G:\GlobalMuOnlineS21v29` — diskdash 37,204 files / 3.08 GiB on disk;
PowerShell `Get-ChildItem -Recurse` 37,204 files / 3.075 GiB rounded to 4 KiB clusters.

## Real drives: G: (SSD) and D: (HDD) in one scan request (2026-10-12)

Release build, non-elevated, hard-link detection off (non-system volumes), HDD 1 thread.

| Drive | Files | Size | Errors | Time |
|---|---|---|---|---|
| G: Samsung 850 EVO (SATA SSD) | 70,664 | 9.5 GiB | 1 | 5 s (in parallel with D:) |
| D: WD 1 TB (HDD, 1 thread) | 554,109 | 881.5 GiB | 10 | 7 min 46 s |

Note: when diskdash is launched from inside the Claude desktop app (a packaged app),
Windows shows the app's virtualised `AppData` folders twice, so a few files appear
duplicated. Launched normally (`start.cmd`) this does not happen.
